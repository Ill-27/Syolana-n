# Развёртывание и эксплуатация пилота

Эта инструкция предназначена для настройки хостинга, а не для запуска терминала на смартфоне. Владелец сможет ежедневно работать в браузере и GitHub после однократной установки.

## Схема

Один сервер с HTTPS → Python WSGI → SQLite + папка загруженных файлов. На том же домене `dist/public` становится корнем статических страниц, `/api` обрабатывает сервер. Папки `platform/data`, `platform/.env`, `dist/private_lessons`, `private_courses` и исходники сервера не публикуются как статика.

Для РФ перед выбором площадки проверить применимость требований локализации и трансграничной передачи. Наличие сервера в РФ само по себе не решает все требования. Шрифты Cormorant Garamond и Nunito находятся в `assets/fonts` с лицензиями OFL и загружаются с вашего домена. В каталоге ещё есть внешние обложки и ссылки; перед запуском проверить их права и обработку запросов внешними ресурсами.

## Локальная проверка

Python 3.12+:

```bash
python3 build.py
python3 platform/server.py
```

Адрес по умолчанию: `http://127.0.0.1:8787`. База создаётся в `platform/data/`. Это сервер разработки; в интернете использовать WSGI-сервер и HTTPS.

```bash
python3 -m unittest discover -s tests -v
node tests/test_player.mjs
```

Тесты работают с временной базой, не затрагивая базу авторов. Транспортные тесты используют подставной аудиообъект; они не заменяют прослушивание реальных файлов в браузере.

## Установка в Docker

В примере используются Docker Compose, Caddy для HTTPS и Gunicorn. Требуются DNS и открытые 80/443 порты. Самостоятельная сборка Docker в этой сессии не проверялась.

1. Взять файлы из проверенной ветки репозитория.
2. В папке `platform` скопировать `.env.example` в `.env`, задать домен и PUBLIC_ORIGIN. Не публиковать `.env` в GitHub.
3. Для поставляемой закрытой сети прокси `TRUST_PRIVATE_PROXY=1`. Порт приложения 8080 не публиковать наружу. В другой схеме доверие прокси нужно настроить отдельно.
4. На сервере выполнить:

```bash
cd platform
docker compose up -d --build
docker compose exec app python manage.py create-admin owner@example.com
```

Команда запросит новый пароль без вывода на экран. Адрес выше заменить настоящим. Веб-страница администратора — `/#/admin`, вход через `/#/studio`.

5. Заполнить операторские документы. Публичная регистрация по умолчанию выключена: открыть `REGISTRATION_OPEN=1` только после готовности документов и проверки потока.
6. Данные лежат в постоянном томе `syolana_data`. Пересборка приложения не должна удалять этот том. Не выполнять удаление томов при обновлении.

## Платежи

Адаптер использует официальный API ЮKassa. Подключение магазина, проверка бизнеса и фискализация выполняются владельцем в кабинете провайдера. Доступность и тарифы необходимо проверить для вашего статуса.

Вебхук: `https://ВАШ-ДОМЕН/api/webhooks/yookassa`. События: `payment.succeeded`, `payment.canceled`, `refund.succeeded`.

Провайдерские ключи только в переменных окружения. `PAYMENTS_ENABLED=1` начинает действовать лишь вместе с `LEGAL_READY=1`, HTTPS и заполненными платёжными/фискальными переменными. Не выбирать налоговые коды произвольно. `ALLOW_TEST_PAYMENTS=1` использовать только на изолированной тестовой установке с тестовыми ключами.

Нельзя считать возврат пользователя по `return_url` подтверждением оплаты. Код предоставляет доступ только после получения состояния платежа через авторизованный запрос к API ЮKassa. Повторное уведомление не добавляет ещё один месяц. После успешного платежа добавляется календарный месяц к оставшемуся доступу.

Это разовая оплата следующего месяца. Сохранение карты и автосписания не реализованы. Если вебхук недоступен, нужен повтор уведомления провайдера или ручная сверка; фоновой автоматической сверки и уведомлений пользователю в пилоте нет.

Возвраты не инициируются автоматически. Оператор делает возврат через кабинет, затем корректирует доступ и фиксирует основание. Событие возврата лишь регистрируется в журнале; частичные возвраты, пересчёт оставшегося доступа и повторные уведомления о возврате требуют ручного рассмотрения. Не обещать автоматический пропорциональный возврат без отдельной реализации.

Для авансовых платежей схема чеков зависит от режима и характера услуги: адаптер передаёт настроенный чек при платеже, но не формирует автоматически чек зачёта предоплаты при оказании услуги. До включения оплаты решить это с провайдером/бухгалтером.

## Обновления и цена

Владельцу: редактирование через GitHub само по себе не обновляет любой сервер. После подключения конкретного хостинга нужно настроить развёртывание выбранной ветки. Универсального деплоя без доступа к хостингу в комплекте нет.

Цена по умолчанию — 100 000 копеек. `CURRENT_PRICE_KOPECKS` меняет новую цену. В пределах `locked_until` сервер использует `locked_price` автора. Витрину и текст тарифа надо обновлять согласованно; при новой цене дополнительно проверить весь платёжный сценарий. В текущем пилоте все цены — 1 000 ₽.

## Бэкапы

```bash
docker compose exec app python manage.py backup /data/backups/2026-09-29
```

Это согласованная копия SQLite и копия загруженных файлов. Создавать новый путь для каждой копии. Выносить копии на отдельное защищённое хранилище; копия в том же томе не защищает от потери всего сервера. Расписание и проверка восстановления обязательны перед платным открытием, но не созданы автоматически без доступа к вашему серверу.

Команда `manage.py prune --days 30` удаляет старые файлы, на которые нет ссылок в черновиках, проверяемых и опубликованных версиях. Запускать только после бэкапа и понимания политики хранения. Изменение пароля через `manage.py reset-password EMAIL` аннулирует все сессии пользователя; сначала проверить его личность.

## Перед масштабированием

Перевести файлы в объектное хранилище, добавить фоновые очереди, проверку медиа, автоматическое восстановление доступа, почту и MFA, контроль расходов, резервирование и наблюдение за доступностью. Для независимых доменов нужны подтверждение владения доменом, маршрутизация арендаторов, сертификаты и отдельная политика cookies. Для нормального SEO нужна серверная выдача отдельных URL книг, а не только hash-маршруты.

Пользовательский HTML и JS намеренно не принимаются. Новые темы добавляет только оператор. Не включать произвольный HTML в редактор без отдельной изоляции и очистки.

## Переход с GitHub Pages

1. Развернуть проверенную ветку на отдельном сервере; сначала проверить её на временном адресе хостинга. Создать администратора.
2. В Cloudflare заменить только DNS-запись сайта на адрес нового сервера. Не менять MX/TXT и настройки почты. `PUBLIC_ORIGIN` и `SITE_DOMAIN` должны соответствовать фактическому домену. Если используется прокси Cloudflare, настроить Full (strict) с действительным сертификатом origin. Доступ к этим настройкам в текущей сессии не предоставлен.
3. Проверить HTTPS, библиотеку, плеер, кабинет и публикацию. Затем отключить старую публикацию GitHub Pages. Сохранить исходную ветку/коммит для отката.
4. Настроить автоматическое развёртывание из GitHub средствами выбранного хостинга. Секреты не хранить в репозитории. `platform/update.sh` предназначен только для сервера и обновляет приложение без удаления тома данных.

Оригинальные платные уроки уже лежали в публичном GitHub. `build.py` защищает серверную выдачу, но не удаляет ранее опубликованные копии из истории. Новые закрытые тексты загружать в приватное хранилище, а не в открытый репозиторий.

Для воспроизводимой установки зафиксирован доступный в PyPI Gunicorn 26.2.0 (WSGI/gthread). Перед обновлением зависимости повторить проверки; Python-сервер разработки не использовать в интернете.
