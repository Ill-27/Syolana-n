# Syolana · обновление 30 сентября 2026

Историческая запись. Актуальные изменения, звуки и доступ GitHub описаны в [обновлении 1 октября](UPDATE-OCTOBER-1.md).

Это проверенные исходники, а не сообщение о публикации. В момент подготовки обновления GitHub отклонил запись из чата: `403 Resource not accessible by integration`. Сервер, платёжный кабинет и DNS не изменены.

## Что готово в этой версии

- Общий баннер «SYOLANA · ВСЕЛЕННАЯ ТВОРЧЕСТВА», круглое фото/видео сверху по центру, акцент на дизайне сайтов.
- Лента с датой, временем, фильтрами и фото/видео. Главное меню: Лента → Книги → Языки → Хочу такой же сайт.
- Единый набор шрифтов для всех тем: Literata для чтения, Syolana Display для заголовков. Последний — переименованная версия Playfair Display с нужными символами. Лицензии сохранены. Четыре WOFF2-файла вместе занимают около 145 КБ. Кнопки и служебные подписи используют системный шрифт устройства.
- Более плотные панели и заметные, плавно меняющиеся цвета читалки.
- Три анимированных превью тем, более активное движение золотой и лунной тем.
- В созерцании: перетаскивание в стороны, колесо мыши или два пальца для движения в глубину; ненавязчивые ссылки-планеты.
- Подсказки о возможностях работают внутри сайта без запроса системных push-уведомлений. Крестик закрывает только текущую подсказку; на будущие подсказки это не влияет. Во время чтения и созерцания подсказки не показываются.
- MP4 в баннере и обложках: muted + autoplay + loop + playsinline. Если браузер блокирует автозапуск, доступны обычные видеоэлементы управления. Системное уменьшение движения и невидимая вкладка учитываются. Гарантировать автозапуск во всех браузерах невозможно.
- Интерфейс больше не ждёт сервер кабинетов. На GitHub Pages запросы к отсутствующему API не запускаются.
- Серверная лента администратора, проверка публикаций, контроль месячного доступа, защита от повторного зачёта номера оплаты, отключение оформления с сохранением опубликованного текста.
- Подготовлен режим оплаты НПД через ЮKassa. Он выключен; чек «Мой налог» эта программа самостоятельно НЕ создаёт.

## Что ещё не запущено

Нет арендованного и настроенного сервера. На GitHub Pages не работают вход, загрузка в облако, очередь публикаций и платёжные операции. Дизайн, существующие книги, музыка, языковые материалы и лента из файла работают без сервера.

Нет постоянно работающей ИИ-модерации, автоматической обработки загружаемых книг, выдачи закрытых книг по кодам и автоматического размещения на независимых хостингах партнёров. Нельзя считать эти функции готовыми или продавать их как уже действующие. Текущие страницы партнёров — маршруты `/#/s/адрес` внутри одного приложения. Выгрузка собственного простого сайта с текстами и медиа реализована отдельно.

Звуковой механизм чтения подготовлен: он проигрывает только явно перечисленные в `config.json → sceneAudio` файлы. Список пуст, потому что в Syolana-n нет согласованной библиотеки звуков. Он не делает несуществующих запросов и не выдаёт отсутствие звука за работающую функцию. Имена в поле `audio` блоков книги сопоставляются с ключами `sceneAudio`. Перед добавлением записи проверьте права. Пример:

```json
"sceneAudio": {
  "forest.ogg": "audio-library/forest.ogg",
  "calm": "audio-library/quiet.mp3"
}
```

Кнопка звуков появляется в читалке, когда список не пуст. Фоновая музыка включается отдельно пользователем; два источника не должны перекрывать друг друга.

## Как установить с телефона

Если запись в GitHub будет доступна, изменения можно перенести автоматически. До этого:

1. Скачайте архив обновления, распакуйте его в «Моих файлах» Samsung.
2. В `Ill-27/Syolana-n` загрузите корневые файлы из папки `ROOT` архива обновления: **Add file → Upload files → Commit changes**. В репозиторий загружаются сами файлы, не папка ROOT.
3. Откройте папку `assets/fonts` в GitHub и загрузите туда содержимое `FONTS`.
4. В `themes` загрузите содержимое `THEMES`.
5. Серверные файлы из `PLATFORM` обновляйте в `platform`, проверки из `TESTS` — в `tests`, документацию из `DOCS` — в `docs`.
6. Откройте опубликованный сайт и обновите страницу. Сам ZIP GitHub Pages не распаковывает.

Для визуального обновления нужны шаги 2–4. Для полного проекта есть отдельный архив с уже правильной структурой папок. Не складывайте содержимое всех папок в корень: так теряются пути к шрифтам, темам и логотипу. Старые font-0.ttf ... font-8.ttf больше не используются; оставшиеся копии на GitHub не мешают запуску.

## Картинка или видео в круге

Откройте `config.json` → карандаш. В `banner.media` замените только значения:

```json
"media": {
  "type": "video",
  "src": "assets/my-banner.mp4",
  "poster": "assets/my-banner.jpg",
  "alt": "Мой творческий мир"
}
```

Сначала загрузите сами файлы в папку `assets`. Для картинки: `"type": "image"`, `"src": "assets/my-banner.jpg"`. Пустой `src` показывает логотип. Регистр букв в пути важен. Квадратное фото или ролик удобнее вписываются в круг. Видео H.264 без звуковой дорожки и небольшой размер файла ускорят загрузку. Постер показывается до готовности видео.

## Как добавлять свои посты

**Сейчас, без сервера:** откройте опубликованный сайт с окончанием `/#/editor`, например `https://ill-27.github.io/Syolana-n/#/editor`. Заполните текст и ссылки на загруженные фото/видео, проверьте предпросмотр, скачайте обновлённый `feed.json`. Загрузите этот файл в корень репозитория вместо прежнего. Локальный черновик хранится только в этом браузере, поэтому не используйте его как единственную копию текста. Если на сайте используется собственный домен, добавьте `/#/editor` к нему.

**После установки сервера:** войдите администратором через `/#/studio`, создайте профиль, например `syolana-news`. Добавляйте посты и одобряйте их через `/#/admin`. Лента администратора автоматически появится на главной. Партнёры используют тот же редактор для собственных сайтов, но не получают прав администратора. Одобрение первой страницы запускает 7 дней тест-драйва. Изменение опубликованного материала не заменяет одобренную версию до повторной проверки.

Редактор не нужно держать в главном меню. Вход доступен внизу раздела «Хочу такой же сайт».

## GitHub: какое разрешение нужно

На присланных скриншотах ChatGPT Codex Connector находится в **Authorized GitHub Apps**, но GitHub пишет, что приложение не установлено ни для одного аккаунта. Проверка подключения также вернула пустой список установок. Авторизация учётной записи и установка доступа к репозиторию — разные действия.

1. Откройте https://github.com/apps/chatgpt-codex-connector/installations/new в браузере, где выполнен вход в GitHub. Это адрес установки приложения **ChatGPT Codex Connector**, разработчик **openai**.
2. Выберите свой аккаунт `Ill-27`.
3. Выберите **Only select repositories**, затем `Syolana-n`.
4. Посмотрите запрашиваемые разрешения и нажмите **Install**. Завершите авторизацию, если GitHub попросит.
5. Проверьте https://github.com/settings/installations: приложение должно появиться во вкладке **Installed GitHub Apps**. Через **Configure** можно проверить выбранный репозиторий.

Если приложение уже установлено: Settings → Applications → Installed GitHub Apps → ChatGPT Codex Connector → Configure → Repository access → Only select repositories → `Ill-27/Syolana-n` → Save. Copilot Chat App — другое приложение и не даёт этому чату доступа.

Раздел Permissions показывает разрешения установленного приложения. Для записи содержимого нужен Contents: Read and write. Выбор All repositories не превращает доступ только для чтения в доступ для записи. Если приложение не запрашивает запись, для работы потребуется подключение Codex с возможностью изменять этот репозиторий. Пароль, GitHub token и коды подтверждения не передавайте в чат.

Официальные инструкции: https://docs.github.com/en/apps/using-github-apps/installing-a-github-app-from-a-third-party и https://docs.github.com/en/apps/using-github-apps/reviewing-and-modifying-installed-github-apps

## Проверка версии

20 серверных интеграционных тестов пройдены. Проверены каталог, обе части «Демона», реальные песни, порядок и повтор плеера, главы из TXT. В браузере проверены экран 412 × 915, отсутствие горизонтального переполнения, три превью, созерцание, смена цвета при прокрутке, непрерывность музыки между разделами, зацикленная видеообложка и французский учебный материал. Проверен полный путь: регистрация → профиль → книга → одобрение → месяц доступа → чтение → защищённый урок → выгрузка сайта. Ошибок JavaScript в этих сценариях не обнаружено.

Это локальная проверка Chromium, не гарантия на всех моделях телефонов. После публикации остаётся проверить фактический GitHub Pages URL и Samsung Internet/Chrome на вашем устройстве. Docker-сборка должна пройти в GitHub Actions или на сервере: в рабочем окружении Docker отсутствует.
