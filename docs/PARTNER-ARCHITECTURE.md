# Архитектура партнёрских сайтов Syolana

## Цель

Каждый партнёр хранит свой сайт и контент у себя, а Syolana поставляет дизайн, темы, иммерсию и обновления.

## Базовая схема

1. У каждого партнёра отдельный GitHub-репозиторий.
2. Репозиторий публикуется через GitHub Pages или другой статический хостинг партнёра.
3. Посты и страницы принадлежат репозиторию партнёра.
4. Общий Syolana Core подключается как удалённый модуль.
5. Доступ к премиальным темам/ассетам проверяется через небольшой entitlement endpoint.
6. При прекращении подписки удалённые премиальные ресурсы перестают выдаваться; собственный контент партнёра остаётся.

## Ограничение защиты

Код и ассеты, которые уже были отправлены в браузер, нельзя сделать на 100% нескопируемыми. Техническое отключение надёжно для будущей выдачи удалённых ресурсов и API, но не отменяет копии, которые кто-то намеренно сохранил раньше. Поэтому техническая защита должна дополняться условиями лицензии.

## Публикация постов без отдельной админки

Наиболее простой сценарий для партнёра:

Партнёр отправляет пост → автоматизация проверяет источник → обновляет feed.json в его репозитории → GitHub Pages пересобирается автоматически.

Варианты источника:

- RSS/Atom — лучший вариант, если площадка его даёт.
- Официальный API соцсети.
- Почта на отдельный publishing-адрес партнёра.
- Простая форма/бот, который передаёт структурированный пост.

Для почтового сценария лучше использовать уникальный адрес на партнёра и список разрешённых отправителей. Автоматизация может либо публиковать сразу, либо безопаснее сначала создавать draft/PR для проверки.
