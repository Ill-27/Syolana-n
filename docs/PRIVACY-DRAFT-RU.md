# Политика обработки персональных данных Syolana — рабочий проект

> Не публиковать как финальную политику до определения оператора, российских баз данных, фактических форм, аналитики и Studio backend.

## Принцип минимизации

Syolana должна собирать только то, без чего не работает выбранная функция.

Предпочтительная модель:

- посетителю партнёрского сайта не нужен аккаунт Syolana;
- контакты партнёра открываются как внешние ссылки на Yandex/VK/Avito;
- публичные посты хранятся в репозитории самого партнёра;
- Partner Studio обрабатывает только данные самого партнёра, необходимые для авторизации и публикации;
- личные сообщения и комментарии VK не импортируются.

## Возможные категории данных

До коммерческого запуска список должен быть сверён с реальным кодом. Потенциально:

- email/логин партнёра;
- технический идентификатор сессии Studio;
- IP/технические журналы безопасности;
- публичные контактные данные, которые партнёр сам решил разместить;
- материалы публикации;
- данные, добровольно отправленные в поддержку.

## Локализация

При сборе персональных данных граждан РФ через интернет архитектура должна учитывать требования ч. 5 ст. 18 152-ФЗ.

Поэтому production Partner Studio проектируется на российской серверной инфраструктуре. В качестве базового варианта рассматриваются Yandex Cloud Functions + API Gateway + YDB Serverless в российском регионе; фактическая конфигурация должна быть отражена в финальной политике до запуска. GitHub остаётся хранилищем публичного контента/кода партнёра, а не первичной базой аутентификационных данных Syolana.

Источник: https://www.consultant.ru/document/cons_doc_LAW_61801/cbf4e15b7c330f9372e876cdf2bc928bad7950ef/

## Сроки хранения

В финальной политике установить конкретные сроки:

- активная Studio-сессия — короткий срок;
- журналы безопасности — минимально необходимый период;
- обращения поддержки — до закрытия вопроса плюс разумный срок защиты прав;
- публичный контент — пока партнёр его не удалит или не заменит.

## Передача третьим лицам

Перечислить только реально используемые сервисы после финального выбора:

- российский backend/облако;
- платёжный провайдер;
- сервис отправки уведомлений;
- GitHub — для публичного репозитория партнёра;
- VK — только при включённом импорте;
- иные сервисы только по фактической необходимости.

## Права пользователя

Финальная политика должна содержать порядок запроса доступа, уточнения, блокирования, удаления, отзыва согласия, когда обработка основана на согласии, и прекращения обработки в предусмотренных законом случаях.

Контакт: syolana@yandex.ru.

## Безопасность

- никаких GitHub/VK/API-секретов в браузере;
- уникальные партнёрские учётные данные;
- короткоживущие серверные сессии;
- rate limiting;
- журналирование административных действий;
- резервное копирование только необходимого;
- удаление неиспользуемых аккаунтов и сессий.

## Перед запуском

1. определить оператора;
2. проверить необходимость и порядок уведомления Роскомнадзора;
3. выбрать российскую первичную базу;
4. заполнить перечень обработчиков;
5. опубликовать финальную политику и согласия только там, где они реально нужны;
6. проверить фактический код против текста политики.
