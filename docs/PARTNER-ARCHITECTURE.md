# Архитектура партнёрских сайтов Syolana

## Цель

Партнёр остаётся владельцем своего домена, хостинга, репозитория и контента. Syolana поставляет подключаемый иммерсивный слой: темы, плеер, читалку, обновления, редактор и автоматизацию публикаций.

Такая схема уменьшает инфраструктурную зависимость партнёра от Syolana и делает разделение ответственности понятнее, но сама по себе не освобождает стороны от требований закона и условий договора.

## Базовая схема

1. Домен регистрируется на партнёра.
2. Хостинг/аккаунт Pages принадлежит партнёру.
3. У партнёра отдельный GitHub-репозиторий.
4. Сайт публикуется через GitHub Pages или Cloudflare Pages в аккаунте партнёра.
5. Публичные посты, изображения и страницы хранятся в репозитории партнёра.
6. Syolana Core подключается как удалённый модуль.
7. Премиальные темы и функции проверяют entitlement endpoint.
8. При окончании подписки собственный сайт и контент партнёра остаются; премиальные ресурсы Syolana перестают выдаваться.

## Онбординг без технических знаний

Партнёру не нужно уметь программировать.

Рекомендуемый процесс:

1. Syolana даёт короткий чек-лист регистрации GitHub/Cloudflare.
2. Партнёр сам владеет аккаунтами и принимает условия сервисов.
3. Из partner-template создаётся его репозиторий.
4. GitHub Pages/Cloudflare Pages подключается автоматически из шаблона.
5. Партнёр выбирает домен: собственный платный домен либо бесплатный технический адрес Pages.
6. Syolana получает только те права, которые нужны для обновления шаблона и публикаций.

## Автоматизация публикаций

Лучший поток для нетехнического партнёра:

Партнёр пишет пост в простом редакторе на своём сайте → serverless endpoint проверяет формат → создаёт draft/PR в ЕГО репозитории → автоматические проверки запускаются → безопасный пост может быть опубликован автоматически → спорный пост уходит в очередь на ручную проверку.

Альтернативные источники:

- RSS/Atom;
- официальный API соцсети;
- почтовый адрес вида publish+slug@syolana.com;
- форма на сайте партнёра.

Syolana не должна хранить постоянную копию публичного поста у себя, если в этом нет необходимости: после обработки источник истины — репозиторий партнёра.

## Модерация

Техническую и форматную проверку можно автоматизировать полностью.

Содержательную модерацию лучше строить в два уровня:

1. автоматическая проверка правил и риска;
2. ручная проверка только пограничных случаев.

Для автоматической публикации партнёр заранее принимает правила Syolana и подтверждает, что именно он является издателем/владельцем контента. Syolana предоставляет инструмент публикации и модерации, но это не является гарантией отсутствия юридических рисков.

## Ограничение защиты

Код и ассеты, уже отправленные браузеру, невозможно сделать на 100% нескопируемыми. Entitlement надёжно прекращает будущую выдачу удалённых премиальных ресурсов и API, но не отменяет сохранённые копии. Поэтому техническая защита дополняется лицензионными условиями.

## Следующий технический этап

1. Создать отдельный partner-template.
2. Сделать один тестовый сайт партнёра в отдельном репозитории.
3. Подключить entitlement endpoint.
4. Добавить форму «Новая публикация», создающую draft/PR.
5. Добавить автоматические проверки.
6. После проверки схемы масштабировать её на новых партнёров.
