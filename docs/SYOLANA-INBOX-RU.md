# Syolana Inbox — безопасная архитектура для запуска в РФ

## Цель

Дать посетителю ощущение настоящего чата внутри Syolana, не заставляя его регистрироваться и не создавая владельцу сайта ещё один ящик, который нужно постоянно проверять.

## Рекомендуемая схема

- Виджет на сайте: «✦ Написать Syolana».
- Российский backend: Yandex API Gateway + Cloud Functions + Serverless YDB.
- Секреты: Lockbox/секреты облака, никогда не публичный GitHub.
- Новый диалог получает случайный conversation_id и отдельный токен посетителя.
- Имя не требуется.
- Email необязателен и нужен только для уведомлений вне сайта.
- Новое сообщение всегда отправляет уведомление на syolana@yandex.ru со ссылкой на диалог.
- Ответ владельца сохраняется в диалоге. Если посетитель оставил email, ему можно отправить уведомление о новом ответе.
- Если email не оставлен, ответ показывается при следующем открытии сайта на том же устройстве.
- Личные адреса владельца Syolana нигде не публикуются.

## Минимизация данных

Хранить только:
- conversation_id;
- сообщения;
- направление сообщения;
- время;
- статус прочтения;
- необязательный email посетителя;
- технический токен диалога в виде хеша.

Не хранить IP-адрес в собственной базе без необходимости. Не просить телефон, ФИО и регистрацию по умолчанию.

## Россия

До коммерческого запуска нужно:
- определить оператора персональных данных;
- опубликовать политику обработки персональных данных;
- проверить необходимость уведомления Роскомнадзора до начала обработки;
- обеспечить требуемую локализацию баз данных граждан РФ;
- определить сроки хранения и удаления диалогов;
- дать пользователю понятный способ удалить/закрыть диалог и обратиться по вопросам данных.

Нельзя обещать «вообще не собираем персональные данные»: пользователь сам может написать персональные сведения в тексте сообщения.

## Уведомления

Администратору:
- каждое новое сообщение -> уведомление на syolana@yandex.ru;
- письмо содержит только минимум: номер диалога, короткий фрагмент и безопасную ссылку на панель;
- полный текст лучше читать после входа в закрытую панель.

Посетителю:
- без email: индикатор нового ответа внутри сайта;
- с email: письмо «В Syolana есть новый ответ», без лишнего содержания;
- отписка/отказ от email-уведомлений в один клик.

## Защита

- CSP и строгий CORS только для доменов Syolana.
- Ограничение размера и частоты сообщений.
- CAPTCHA/anti-abuse при подозрительной активности.
- HTML из сообщений не исполняется.
- Все тексты выводятся как textContent.
- Админ-панель с отдельной авторизацией и 2FA.
- Никаких API-ключей в клиентском JS.
- Резервное копирование и журнал действий администратора.

## Почему не GitHub

Личные чаты не хранить в Git:
- история Git долговечна;
- неудобно гарантированно удалять отдельные сообщения;
- в переписке могут появляться персональные данные.

GitHub использовать для публичных постов и контента партнёров, а не для личной поддержки.
