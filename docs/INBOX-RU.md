# Syolana Inbox — рекомендуемая архитектура для РФ

> Не включать публично до настройки российского backend и финальной политики обработки персональных данных.

## Что видит посетитель

Плавающая кнопка «✦ Написать Syolana».

Регистрация не нужна. Имя и email необязательны.

Браузер получает случайный идентификатор беседы. История доступна только этому браузеру по случайному токену.

## Где хранить сообщения

Для запуска в России рекомендуется хранить первичную базу сообщений в российской инфраструктуре.

Практичный вариант:

- Yandex Cloud Functions или Serverless Containers — API;
- YDB serverless — сообщения и статусы;
- API Gateway — публичный HTTPS endpoint;
- Postbox или другой подходящий почтовый сервис — уведомления.

Yandex Cloud документирует serverless Functions и YDB; у serverless-сервисов есть free tier, но актуальные лимиты нужно проверять перед коммерческим запуском.

## Минимизация данных

По умолчанию сохранять только:

- conversation_id;
- случайный access_token/hash;
- текст сообщения;
- роль sender/operator;
- timestamp;
- статус прочтения.

Не требовать имя, телефон или email.

Email сохранять только если посетитель добровольно включает «Получать ответы на почту».

Не записывать IP в прикладную базу без необходимости.

## Уведомления

Новое сообщение посетителя:

1. записывается в YDB;
2. на syolana@yandex.ru приходит короткое уведомление со ссылкой на закрытую панель Syolana Inbox;
3. текст полного сообщения можно не дублировать в email, если нужна минимизация данных.

Ответ оператора:

- появляется в чате;
- если пользователь оставил email и включил уведомления — ему отправляется уведомление «В Syolana есть новый ответ» со ссылкой обратно в чат.

## Панель оператора

Закрытая страница:

- список бесед;
- непрочитанные;
- поиск;
- ответ;
- закрыть/архивировать;
- удалить;
- экспорт по запросу пользователя.

## Защита

Обязательно:

- rate limit;
- CAPTCHA/Turnstile только при подозрительной активности;
- CSRF/CORS;
- длина сообщения и размер вложений;
- HTML не принимать, только текст/безопасный Markdown;
- шифрование секретов;
- отдельная админ-аутентификация;
- журнал действий администратора;
- сроки хранения и автоматическое удаление старых чатов.

## Юридический запуск

До публичного включения:

1. определить лицо/статус оператора;
2. опубликовать политику обработки персональных данных;
3. определить правовое основание обработки;
4. проверить необходимость уведомления Роскомнадзора до начала обработки;
5. обеспечить требуемую локализацию базы в РФ;
6. указать срок хранения и порядок удаления.

Роскомнадзор указывает, что в общем случае оператор уведомляет уполномоченный орган до начала обработки персональных данных; применимость исключений нужно проверять для конкретной схемы.
