# Управление партнёрами Syolana

## Ручное включение/отключение

В репозитории Syolana-n есть workflow:

Partner access — manual switch

Поля:

- partner_id — ID из integration.json партнёрского сайта;
- state — on или off;
- allowed_hosts — допустимые домены через запятую;
- note — внутренний комментарий.

## Включение

1. Открыть Actions.
2. Выбрать Partner access — manual switch.
3. Run workflow.
4. Указать partner_id.
5. state = on.
6. При первом подключении указать домены.

После коммита центрального реестра новый визит на партнёрский сайт получает Syolana Core.

## Отключение

То же самое, но state = off.

После обновления реестра новый визит не получает:

- логотипы Syolana;
- баннер;
- темы;
- фирменные шрифты;
- плеер;
- режим созерцания;
- рекламные объекты Syolana.

Собственный сайт и контент партнёра остаются.

## Окончательное отсоединение

В репозитории партнёра можно запустить workflow Detach optional platform layer. Он удаляет loader Syolana из репозитория партнёра.

## Приоритет ручного решения

Даже после подключения автоматической оплаты ручное состояние остаётся главным административным переключателем. Платёжный webhook не должен автоматически включать сайт, если на партнёра установлен административный запрет.

Для production entitlement рекомендуется хранить отдельно:

- billingActive;
- manualState: inherit/on/off;
- effectiveActive;
- reason;
- updatedAt.

effectiveActive рассчитывается так, чтобы manualState=off всегда выключал Syolana.
