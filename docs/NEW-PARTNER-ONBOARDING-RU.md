# Подключение нового партнёра — рабочая схема

## 1. Кто владеет инфраструктурой

Новый партнёр должен быть владельцем:

- своего GitHub-аккаунта;
- своего репозитория сайта;
- своего аккаунта Pages/хостинга;
- своего домена, если он подключён;
- собственных публикаций и медиа.

Syolana получает только необходимый доступ для настройки и поддержки.

## 2. Как передать код

Предпочтительно партнёр создаёт новый репозиторий из `Ill-27/Syolana-partner-template`.
Если кнопка шаблона недоступна, партнёр создаёт пустой репозиторий, а Syolana копирует в него содержимое template.

## 3. Как дать Syolana доступ

На время первоначальной настройки партнёр:

1. приглашает GitHub-пользователя `Ill-27` в репозиторий;
2. даёт достаточные права для настройки GitHub Pages/Actions и файлов;
3. разрешает GitHub-интеграции ChatGPT доступ именно к этому репозиторию.

После первичной настройки права можно уменьшить до минимально необходимых для обновлений и поддержки. Владельцем репозитория остаётся партнёр.

## 4. Что настраивает Syolana

- `partner.json`;
- контакты партнёра;
- категории и стартовые публикации;
- GitHub Pages / выбранный хостинг;
- `partnerId` и разрешённый hostname;
- центральный Syolana entitlement;
- Partner Studio и VK-import, когда production backend подключён.

## 5. Ручное включение

В `Syolana-n`:

GitHub → Actions → **Partner access — manual switch** → `enable`.

Указываются:

- `partner_id`;
- hostname партнёра;
- необязательная внутренняя заметка.

## 6. Ручное отключение

Тот же workflow → `disable`.

После этого центральный Core не должен загружаться. Production Partner Studio также проверяет тот же центральный entitlement и при отключении возвращает отказ в публикации.

Это ручное отключение остаётся доступно всегда, даже если позже появится автоматическая проверка оплаты.

## 7. Полное техническое расставание

Если доступ к репозиторию ещё есть, Syolana может запустить workflow **Detach optional platform layer**, который удаляет loader и integration.json.

Даже без этого центральное отключение прекращает выдачу активного слоя Syolana и убирает его видимые элементы с сайта.

Нельзя технически гарантировать удаление строк из чужого репозитория, если владелец заранее отозвал доступ. Поэтому репозиторий не должен содержать закрытые компоненты или секреты Syolana; право использования прекращается одновременно с центральным отключением, а обязанность не использовать компоненты после прекращения сотрудничества фиксируется в оферте.
